# Harden G1/G2/G8 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build three blocking Claude Code hooks (G1 report contract, G2 Orchestrator no-write, G8 Worker may not edit DONE_WHEN tests) with a deterministic hook-level X1 runner, without registering anything in `~/.claude`.

**Architecture:** Small stdlib-Python scripts in `hooks/`, each a thin `main(event) -> Decision` run through one fail-closed wrapper in `hooks/lib/common.py`. Tests feed crafted hook-input JSON to the scripts by subprocess; a block counts only if exit code 2 and a logged `blocked: true` event with matching `guardrail` and `case_id`.

**Tech Stack:** Python 3 stdlib, `python3 -I`, `unittest`, bash only for the probe.

**Spec:** `docs/superpowers/specs/2026-11-25-harden-g1-g2-g8-design.md` (read §5, §6, §9 first; §9 holds late decisions)

## Global Constraints

- Python 3 stdlib only; every command run as `python3 -I`. Scripts add their own directory to `sys.path` (`-I` drops the cwd).
- Hooks are inert (allow, exit 0, no log) unless env `AGENT_WORKFLOW=1`.
- Blocking = exit code 2 with the reason on stderr. Any exception, unparsable stdin or missing required field in a blocking hook → log `blocked: true, reason: hook_error`, exit 2. `g8_capture.py` never exits 2.
- Event line appended to `${AGENT_DASHBOARD_DIR:-~/.claude/agent-dashboard}/events.jsonl`: `{"event":"guardrail_hit","guardrail":"G<n>","blocked":bool,"case_id":<env AGENT_HOOK_CASE_ID or null>,"rule_version":"<hook>-v1","tool_name":...,"path":...,"reason":...,"ts":ISO8601}`.
- State dir `${AGENT_HOOK_STATE_DIR:-~/.claude/agent-hook-state}`. Tests and the runner always set both env vars to temp dirs; nothing in this plan reads or writes the real `~/.claude`.
- Path checks use `os.path.realpath` (symlink aliases).
- Never modify `headless-dashboard/`. Never register hooks in `settings.json`. No `install-hooks.sh`.
- `hooks/guardrails.yaml` G1–G8 existing text unchanged; only add `hook:`, `implemented:`, `residual:` fields to G1, G2, G8. `enforced` stays `false`.
- `agents/orchestrator.md`: add only the one `DONE_WHEN_FILES:` convention line.
- Commits end with `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`. Branch `feat/dashboard-v2` as is; no remote, no push.
- Hook input field names below (`session_id, cwd, tool_name, tool_input.file_path, tool_input.command, agent_id, agent_type`) come from the hooks docs [E413]; `tool_input.prompt`, `tool_input.subagent_type`, and the SubagentStop final-message and `stop_hook_active` fields are UNVERIFIED until Task 1. After Task 1, `hooks/tests/fixtures/PROBE.md` overrides this plan wherever they differ.

## Review Focus

1. Symlink alias of a DONE_WHEN file (repo path vs `~/.claude`-style link) must still deny → Task 4.
2. Hook crash, empty stdin, or invalid JSON must deny, never allow → Tasks 2, 3, 4, 5 (each hook).
3. A Worker creating a NEW test file (not a DONE_WHEN file) must be allowed when DONE_WHEN state is known → Task 4.
4. SubagentStop re-fires after a G1 block: `stop_hook_active` true must allow, not loop → Task 5.
5. DONE_WHEN file given relative with the hook's cwd different from the dispatcher's → Task 4.
6. `AGENT_WORKFLOW` unset: a would-be violation passes untouched and nothing is logged → Tasks 3, 4, 5.
