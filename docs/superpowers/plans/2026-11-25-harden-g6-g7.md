# Harden G6 and G7 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Blocking PreToolUse hooks for G6 (Advisor writes only inside its memory folder) and G7 (Worker writes only inside the git root), with tests that try to break them and X1 hook-level fixtures.

**Architecture:** Two role-specific hook scripts built on `hooks/lib/common.py` (`run_hook`, `Decision`, `role`, `real`), sharing one new module `hooks/lib/shellscan.py` that finds the paths a Bash command would write. Same shape as G2/G8: inert unless `AGENT_WORKFLOW=1`, exit 2 blocks, any error denies. Nothing is registered in `~/.claude`.

**Tech Stack:** Python 3 stdlib only, run as `python3 -I`; `unittest`; JSON fixtures run by `hooks/tests/run_x1.py`.

**Spec:** `docs/superpowers/specs/2026-11-25-harden-g6-g7-design.md` (continues `2026-11-25-harden-g1-g2-g8-design.md`).

## Global Constraints

- Test command for the suite: `python3 -B -m unittest discover -s hooks/tests -p 'test_*.py'` (baseline: 99 tests OK). X1: `python3 -B hooks/tests/run_x1.py` (baseline: blocked 32/32, false_blocks 0/12). Use `-B` so no `.pyc` files are written.
- Hooks read no environment variable except `AGENT_WORKFLOW`, `AGENT_DASHBOARD_DIR`, `AGENT_HOOK_STATE_DIR`, `AGENT_HOOK_CASE_ID` (existing) and the new `AGENT_ADVISOR_MEMORY_DIR` (G6 root override, default `~/.claude/agent-memory/advisor`).
- Every hook script keeps the import guard around `from lib import common` (exit 2 when `AGENT_WORKFLOW=1` and `lib/` is missing).
- A deny must never depend on the event log (`run_hook` already guarantees this; do not bypass it).
- Event fields as before: `guardrail`, `blocked`, `case_id`, `rule_version` (`g6-v1`, `g7-v1`), `tool_name`, `path`, `reason`.
- Do not edit `agents/*.md`, `hooks/g8_*.py`, `PROTECTED.paths`, `~/.claude/*`, `headless-dashboard/`. `enforced` stays `false` for every guardrail.
- Write tools are `Write`, `Edit`, `NotebookEdit`, `MultiEdit`; the path is `tool_input.file_path` or `tool_input.notebook_path`; a missing path is a hook error (deny).
- Commits end with `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`. Commit with explicit pathspecs; never add `__pycache__`.

## Review Focus

1. A symlink inside the allowed root that points outside it, and a symlink outside that points into the memory dir: judged by realpath (tests in Tasks 2 and 3).
2. A path that differs only by case, or goes through `..`: `inside()` compares case-folded real paths (Task 1 unit test, Task 2/3 hook tests).
3. Bash that hides its target: `$VAR`, backticks, `cd /tmp && echo x > f`, `python -c`, `bash -c`: denied as `unsafe` for writing segments (Task 1, 2, 3).
4. G7 root discovery: cwd in a subdirectory, a git worktree (`.git` is a file), and a cwd with no `.git` above it (deny every write, fail closed) (Task 3).
5. False blocks: read-only Bash, `pytest`, in-root writes, in-memory writes, and a role the hook does not govern must exit 0 (Tasks 2, 3, 4).

### Task 1: `hooks/lib/shellscan.py`

**Files:**
- Create: `hooks/lib/shellscan.py`, `hooks/tests/test_shellscan.py`

**Interfaces:**
- Consumes: `lib.common.real(path, cwd) -> str`.
- Produces:
  - `@dataclass Scan(targets: list[str], unsafe: bool, why: str)`
  - `scan(cmd: str, cwd: str) -> Scan`: `targets` are real paths the command would write (or may write); `unsafe` is true when a writing segment's target cannot be known; `why` is a short human reason (empty when safe).
  - `inside(path: str, root: str) -> bool`: true when the real path equals or lies under the real root, compared case-folded, no trailing-slash tricks.
  - Used by Tasks 2 and 3.

Rules for `scan` (decided here; the implementer writes the body):
- Split on `;`, `&&`, `||`, `|`, newline. Strip fd redirects (`2>&1`, `>&2`, `>/dev/null`, `&>/dev/null`) before analysis.
- Tokenise each segment with `shlex`. An unparseable segment is `unsafe` (`why` mentions it).
- A segment is *writing* if it has a redirect `>` or `>>`, or a word in `tee truncate mv cp rm dd ln install touch chmod chown patch`, or `sed -i`/`--in-place`, or `perl -i`, or `git` followed by `checkout|restore|stash|apply`.
- A segment is *unknowable* (always `unsafe`) if its command word is `python|python3|node|perl|ruby` with `-c` or `-e`, or `sh|bash|zsh` with `-c`, or `eval`.
- Read-only segments (first word after leading `VAR=` assignments is in `cat grep head tail ls diff wc pytest`, or `python|python3` with `-m pytest|unittest`, or `git diff|status|log|show`) that are not writing contribute nothing.
- Targets: for a redirect, the redirect target words only; for a writing command word, every non-option word after the command word. Expand globs against `cwd`; resolve with `common.real`; expand a leading `~`.
- A writing segment containing `$` or a backtick is `unsafe`. If any segment's first word is `cd`, `pushd` or `popd`, or any word is `-C` or `--directory`, and any segment is writing, the command is `unsafe` (relative paths can no longer be trusted).

- [ ] **Step 1: Write the failing tests** in `hooks/tests/test_shellscan.py` (import via `sys.path.insert` of `hooks/`, as `test_common.py` does). Tests, each on a temp dir `d`:
  - `test_inside_equal_and_child`: `inside(d, d)` and `inside(d + "/a/b", d)` true; `inside(d + "-x", d)` false.
  - `test_inside_dotdot_and_case`: `inside(d + "/a/../../etc", d)` false; `inside(d.upper() + "/a", d)` true only if `d.upper() != d` (case-folded compare of the strings; use a path built from `/Tmp/X` vs `/tmp/x` literals so the test does not need the filesystem).
  - `test_inside_symlink_out`: symlink `d/lnk -> /tmp`; `inside(d + "/lnk/f", d)` false.
  - `test_redirect_target`: `scan("echo hi > out.txt", d).targets == [realpath(d/out.txt)]`, `unsafe` false.
  - `test_redirect_ignores_other_words`: `scan("echo hi > out.txt", d)` has no target for `hi`.
  - `test_tee_cp_mv_rm_touch_sed_i`: each of `tee f`, `cp a b`, `mv a b`, `rm f`, `touch f`, `sed -i s/a/b/ f` yields the non-option words as targets.

  - `test_cd_then_write_unsafe`: `cd /tmp && echo x > f` is `unsafe`; `cd /tmp && ls` is not.
  - `test_interpreters_unsafe`: `python3 -c 'open("f","w")'`, `bash -c 'echo x > f'`, `eval "echo x > f"`, `node -e 1` are `unsafe`.
  - `test_unparseable_segment_unsafe`: `echo "unterminated > f` is `unsafe`.
  - `test_glob_expanded`: with `d/a1`, `d/a2` existing, `rm a*` targets both.
  - `test_pipe_segments`: `cat f | tee out.txt` targets only `out.txt`.
